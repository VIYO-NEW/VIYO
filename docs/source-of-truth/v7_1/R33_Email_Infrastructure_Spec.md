## 1. Dual-ESP Architecture

VIYO utilizes two distinct Email Service Providers (ESPs) to strictly isolate reputation risk.

### 1.1 Tier 1: Platform Transactional (Resend)
- **Purpose:** Delivery of critical system emails (password resets, invites, billing).
- **Sender Domain:** `viyo.app` (e.g., `notifications@viyo.app`).
- **IP Strategy:** Shared, high-reputation IP pool managed by Resend.

### 1.2 Tier 2: Customer Marketing (Amazon SES)
- **Purpose:** Delivery of all campaigns generated by VIYO customers.
- **Sender Domain:** The customer's explicitly authenticated domain.
- **Tenant Isolation:** Strict enforcement via SES Configuration Sets. Every outbound email is tagged with a Configuration Set uniquely mapped to the originating `workspace_id`.

## 2. Domain Authentication & Verification

Customers cannot send emails until their domain is cryptographically verified.

### 2.1 Verification Flow
1. **Initiation:** Customer enters domain in Admin UI.
2. **Record Generation:** VIYO generates SPF (`v=spf1 include:_spf.viyo.app ~all`), DKIM (3 CNAMEs), and DMARC (`v=DMARC1; p=none;`) records.
3. **Automated Polling:** Inngest cron job polls DNS until propagation succeeds.
4. **Activation:** Domain status updates to `active` in `verified_domains`.

## 3. Deliverability & Reputation Management

### 3.1 Automated Warm-up
Newly verified domains undergo an automated warm-up schedule:
- **Day 1:** Max 100 emails.
- **Days 2-7:** 20% daily increase.
- **Days 8-14:** 50% daily increase.
- Excess emails queue in Inngest for subsequent days.

## 4. Blueprint Depth: Event/Webhook Cross-Wiring

To satisfy the Fortune 50 standard, the exact interface points, data flows, and webhook payload schemas between SES, Inngest, and the Render API are defined below.

### 4.1 System Interface Points
- **Event Source:** Amazon SES emits delivery events (Bounce, Complaint, Delivery) to an Amazon SNS topic.
- **Message Queue:** The SNS topic routes the event to an Amazon SQS queue.
- **Ingestion Layer:** The Render API (Hono) exposes an endpoint (`POST /api/v1/webhooks/ses`) that acts as an Inngest event source.
- **Processing Layer:** Inngest workers pull events from the queue, process the payload, and update the Supabase `suppression_list` table.

### 4.2 Webhook Payload Schema (Hard Bounce)

The system must handle the following standard JSON payload structure from SES/SNS:

```json
{
  "Type": "Notification",
  "MessageId": "165545c9-2a5c-472c-8df2-7ff2be2b3b1b",
  "TopicArn": "arn:aws:sns:us-east-1:123456789012:viyo-ses-events",
  "Message": {
    "notificationType": "Bounce",
    "bounce": {
      "bounceType": "Permanent",
      "bounceSubType": "General",
      "bouncedRecipients": [
        {
          "emailAddress": "recipient@example.com",
          "action": "failed",
          "status": "5.1.1",
          "diagnosticCode": "smtp; 550 5.1.1 The email account that you tried to reach does not exist."
        }
      ],
      "timestamp": "2026-04-29T14:32:00.000Z",
      "feedbackId": "0100017a1b2c3d4e-5f6g7h8i-9j0k-1l2m-3n4o-5p6q7r8s9t0u-000000"
    },
    "mail": {
      "timestamp": "2026-04-29T14:31:55.000Z",
      "source": "sender@customer-brand.com",
      "messageId": "0100017a1b2c3d4e-5f6g7h8i-9j0k-1l2m-3n4o-5p6q7r8s9t0u-000000",
      "tags": {
        "ses:configuration-set": ["ws_67890fghij"]
      }
    }
  },
  "Timestamp": "2026-04-29T14:32:01.123Z"
}
```

### 4.3 Idempotency and Failure Handling
- **Idempotency:** The Inngest worker must verify if the `MessageId` has already been processed (using Upstash Redis as a deduplication lock) before writing to the database.
- **Handling Bounces:** Hard bounces (`bounceType: "Permanent"`) immediately add the `emailAddress` to the workspace's `suppression_list`. Soft bounces (`bounceType: "Transient"`) are retried 3 times over 24 hours.
- **Handling Complaints:** Spam complaints immediately suppress the address. If a workspace exceeds a 0.1% complaint rate, the `workspaces.status` is set to `suspended` and an alert is sent to the DevOps Lead.

## 5. Compliance & Footer Enforcement

- **Mandatory Unsubscribe:** The `footer_standard` composable section automatically injects the `{{viyo.org.unsubscribe_url}}` tag.
- **One-Click Unsubscribe:** The `List-Unsubscribe-Post: List-Unsubscribe=One-Click` header is injected into all outbound marketing emails (RFC 8058).
- **Physical Address:** CAN-SPAM regulations are enforced via the `{{viyo.org.physical_address}}` tag.
- **Clipping Protection:** If compiled HTML exceeds 102kb, the UI warns the user and prevents sending until simplified, ensuring the footer remains visible in Gmail.
